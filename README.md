# PDFX 1.4 — write PDF files in AutoIt, with no dependency

PDFX writes valid PDF 1.7 files from plain AutoIt. No COM, no external DLL, no
binary next to the script: a single `#include`.

```autoit
#include "PDFX.au3"

Global $pdf = _PDFX_New("A4", "P", 20)         ; A4 portrait, 20 mm margins
_PDFX_SetCompression($pdf, 6)                  ; content streams as FlateDecode
_PDFX_SetFont($pdf, "Helvetica", 22, "B")
_PDFX_SetFill($pdf, 0x1F3864)
_PDFX_Text($pdf, _PDFX_Mm(20), _PDFX_Mm(20), "Hello")
_PDFX_AddBookmark($pdf, "Introduction", 0, 1)  ; bookmark to page 1
_PDFX_SetPageMode($pdf, "UseOutlines")         ; bookmarks pane open
_PDFX_Save($pdf, @ScriptDir & "\demo.pdf")
_PDFX_Close($pdf)
```

The resulting file opens in Acrobat, Chrome, Edge, Firefox, SumatraPDF, Preview,
and passes any strict validator.

**Author: Numeric1** — [AutoItScript forum](https://www.autoitscript.com/forum/).
MIT licence or public domain, at your choice.

PDFX is an original implementation, written from the ISO 32000-1 standard and
the public AFM metrics of the Core 14 fonts. No code, text or comment is taken
from AutoItObject, MPDF or any other UDF; only the conventional layout of AutoIt
documentation blocks (`#INDEX#`, `#CURRENT#`, `#FUNCTION#`) is shared, as in any
official include.

A complete developer guide is generated by PDFX itself:
[`Guide/PDFX_Developer_Guide.pdf`](Guide/PDFX_Developer_Guide.pdf).

## 1. The mental model

A document is an **array** (the handle). Every function receives it as its first
argument and modifies it. AutoIt passes arrays by reference: there is no need to
write `ByRef` at the call site.

```autoit
Global $pdf = _PDFX_New("A4")       ; creates page 1
_PDFX_AddPage($pdf)                 ; page 2
_PDFX_Text($pdf, 56, 56, "Page 2")
_PDFX_Save($pdf, "doc.pdf")         ; writes everything at once
_PDFX_Close($pdf)                   ; optional: releases GDI+ at the end of the script
```

Nothing is written before `_PDFX_Save`. The document is built in memory as
indirect objects; the xref table and the trailer are computed at save time.

## 2. Coordinates and units

| | Native PDF | PDFX |
|---|---|---|
| Origin | **bottom-left** corner | **top-left** corner |
| Y axis | grows upwards | grows downwards |
| Unit | point (1/72") | point (1/72") |
| A4 | 595.28 × 841.89 | same |

`_PDFX_Mm(20)` converts 20 mm to points. `_PDFX_Text($pdf, x, y, ...)` places the
**top** of the text at `y`: the coordinate you read is the one you see.

Formats: `A3`, `A4`, `A5`, `Letter`, `Legal`, or `"120x200"` (mm).
Orientation: `"P"` or `"L"`.

## 3. Fill, stroke, opacity

```autoit
_PDFX_SetFill($pdf, 0x1F3864)        ; 0xRRGGBB
_PDFX_SetStroke($pdf, "navy")        ; name, [r,g,b] or "r,g,b"
_PDFX_SetLineWidth($pdf, 0.8)
_PDFX_SetDash($pdf, 3, 2)            ; 3 pt on, 2 pt off
_PDFX_SetAlpha($pdf, 0.25)           ; 25 % — applies to the following drawings
```

Shapes take `$PDFX_STROKE`, `$PDFX_FILL` or `$PDFX_BOTH`.

Inputs are **clamped without throwing**: a colour component outside `[0, 255]`
or an opacity outside `[0, 1]` is brought back into range, and `@error` is `1`
to report the correction. `_PDFX_SetDash($pdf, 0)` restores a solid line
(`[] 0 d`); `_PDFX_SetDash($pdf, 3)` uses 3 pt on / 3 pt off.

## 4. Text

```autoit
_PDFX_SetFont($pdf, "Helvetica", 10)        ; family, size, style
_PDFX_Text($pdf, x, y, "Text", 0)           ; 0 = current size
_PDFX_TextAlign($pdf, x, y, width, "Text", "C")   ; L, C, R
Local $yNext = _PDFX_TextWrap($pdf, x, y, width, $long, 10, 12)
```

`_PDFX_TextWrap` returns the ordinate of the next paragraph, so blocks chain
naturally:

```autoit
Local $y = _PDFX_Mm(40)
$y = _PDFX_TextWrap($pdf, _PDFX_Mm(20), $y, _PDFX_Mm(170), $paragraph1, 10)
$y = _PDFX_TextWrap($pdf, _PDFX_Mm(20), $y + _PDFX_Mm(3), _PDFX_Mm(170), $paragraph2, 10)
```

`_PDFX_TextWidth($pdf, $text, $size)` returns the exact width in points,
computed from the real AFM metrics of the font — not an approximation.

### Fonts

Three families, the fourteen standard PDF fonts (no file to embed, no licence):

| Family | Styles |
|---|---|
| `Helvetica` (or `Arial`, `sans`) | regular, `B`, `I`, `BI` |
| `Times` (or `serif`) | regular, `B`, `I`, `BI` |
| `Courier` (or `mono`) | regular, `B`, `I`, `BI` |

**WinAnsi** encoding: Latin-1 text, typographic quotes and symbols pass through
— `é à ç ù ê ï ô œ Œ « » € — ° ± · …`. Characters outside WinAnsi (CJK,
Cyrillic, emoji) are replaced by `?`.

## 5. Shapes

```autoit
_PDFX_Line($pdf, x1, y1, x2, y2)
_PDFX_Rect($pdf, x, y, w, h, $PDFX_FILL)
_PDFX_RoundRect($pdf, x, y, w, h, radius, $PDFX_BOTH)
_PDFX_Ellipse($pdf, cx, cy, rx, ry, $PDFX_FILL)
_PDFX_Circle($pdf, cx, cy, r, $PDFX_STROKE)
_PDFX_Polyline($pdf, $aPoints, $close, $PDFX_FILL)   ; [n][2] = [[x,y], ...]
_PDFX_Bezier($pdf, x1, y1, c1x, c1y, c2x, c2y, x2, y2, $style)
```

## 6. Images

```autoit
_PDFX_Image($pdf, "photo.jpg", x, y, width, height)      ; 0 = inferred
_PDFX_ImageFit($pdf, "logo.png", x, y, boxW, boxH, "C")
Local $a = _PDFX_ImageInfo($pdf, "photo.jpg")            ; [pxW, pxH, ptW, ptH, bytes, ext]
```

- **JPEG**: the stream is copied as is (`/DCTDecode`). Zero re-encoding, zero
  loss, PDF size ≈ JPEG size. RGB, CMYK and grayscale components are recognized
  automatically. A CMYK JPEG carrying the Adobe APP14 marker is declared with
  `/Decode [1 0 1 0 1 0 1 0]`, because Adobe stores the values inverted; without
  that marker, the PDF order is respected.
- **PNG, BMP, GIF**: converted to JPEG through GDI+ on a white background (the
  alpha channel is flattened — the intended behaviour for print).
- **Dimensions**: width only → height inferred; height only → width inferred;
  both → proportions forced; neither → natural size at 96 dpi.
- **Deduplication**: an image inserted ten times is stored once (cache keyed by
  absolute path, a single XObject).

## 7. Paginated tables

```autoit
Local $aColumns[3][3] = [ _
    ["Description", 0.60, "L"], _
    ["Qty",         0.15, "C"], _
    ["Total",       0.25, "R"]]

Local $aRows[2][3] = [ _
    ["Design",   "1", "1,450.00"], _
    ["Printing", "2",   "640.00"]]

Local $y = _PDFX_Table($pdf, x, y, width, $aColumns, $aRows, _
    "padding=6;fontsize=9;zebra=1;headfill=0x1F3864;headcolor=0xFFFFFF")
```

Width fractions are normalized: `0.6 / 0.15 / 0.25` and `6 / 1.5 / 2.5` give
the same result. The table adds a page and repeats its header when it overflows.
It returns the free ordinate below the last row.

| Option | Default | Role |
|---|---|---|
| `padding` | 4 | inner cell margin, in points |
| `fontsize` | current size | body size |
| `headfill` | `0xE8EEF7` | header background (`-1` for none) |
| `headcolor` | `0x1F3864` | header text colour |
| `zebra` | 0 | 1 = alternating rows |
| `zebracolor` | `0xF7F9FC` | background of even rows |
| `border` | 0.5 | rule thickness (0 = none) |
| `bordercolor` | `0xBFC9D9` | rule colour |
| `pagebreak` | 1 | 0 = no automatic page break |

## 8. Header, footer, links, metadata

```autoit
_PDFX_SetHeader($pdf, "Company", "", "Report 2026")
_PDFX_SetFooter($pdf, "", "Page {page} / {pages}", "{date}")
_PDFX_Link($pdf, x, y, w, h, "https://www.autoitscript.com/")
_PDFX_SetMeta($pdf, "Title", "Author", "Subject", "key, words")
```

Both functions accept four extra settings, specific to header and footer:

```autoit
_PDFX_SetHeader($pdf, "Internal", "", "Report", 8, "Courier", "B", 0x1F3864)
_PDFX_SetFooter($pdf, "", "Page {page} / {pages}", "", 7, "Times", "I", 0x6B7280)
```

| Parameter | Default | Role |
|---|---|---|
| size | 8 | text size, shared by header and footer |
| family | `Helvetica` | `Helvetica`, `Times` or `Courier` |
| style | regular | any combination of `B` and `I` |
| colour | `0x666666` | text colour, and rule colour for the header |

`{page}`, `{pages}` and `{date}` are substituted at save time. The header and
the footer are drawn **after** the content: they remain visible on coloured
backgrounds.

## 9. Navigation: bookmarks, internal links, opening mode

A PDF can carry its own table of contents. PDFX writes the bookmarks pane, the
clickable areas that lead to it, and the opening mode of the document.

```autoit
_PDFX_AddBookmark($pdf, "Cover", 0, 1)                  ; level 0, page 1
_PDFX_AddBookmark($pdf, "Chapter 1", 1, 3)              ; below the previous one
_PDFX_AddBookmark($pdf, "Section 1.1", 2, 3, _PDFX_Mm(120))  ; page 3, 120 mm from the top
_PDFX_LinkPage($pdf, x, y, w, h, 5)                          ; clickable area to page 5
_PDFX_SetPageMode($pdf, "UseOutlines")                       ; pane open
_PDFX_SetPageLayout($pdf, "SinglePage")
```

### Bookmarks

`_PDFX_AddBookmark($pdf, title, level, page, y)` accepts a 1-based page and an
ordinate **in points from the top**, like the rest of the API. Without an
ordinate, the destination is `/Fit`: the whole page is shown. With one, it
becomes `/XYZ` and the reader places that point at the top of the window.

- Levels are 0-based. A bookmark can descend at most one level below the
  previous one: a deeper request is clamped to that maximum, without error. An
  outline therefore always stays valid.
- The function returns the ordinal number of the bookmark (1, 2, …), or `-1`
  with `@error = 1` if the title is empty or the page is outside the document.
- The tree is complete: `/Parent`, `/Prev`, `/Next`, `/First`, `/Last`, `/Count`.
  A node's `/Count` is its number of descendants; the root's is the total. The
  counts are positive, so every node is open.
- ASCII titles are written as literal strings, others as **UTF-16BE**
  hexadecimal; an accented title stays exact in the reader's pane.
- Without an explicit mode, the presence of bookmarks is enough:
  `/PageMode /UseOutlines` is added to the catalog automatically.

### Internal links

`_PDFX_LinkPage($pdf, x, y, width, height, page, yTarget)` turns a rectangle
into a `/Subtype /Link` annotation. Coordinates follow the usual system
(top-left, points); the PDF conversion is done by the engine.

The important point: **the target page may not exist yet**. That is the case of
a table of contents written before the chapters. The engine keeps the request
pending and writes it at save time, when every page has its object number.
There is therefore no fake `[0 0 R]` destination and no second pass to manage.

A target page that does not exist at save time is **ignored without error**: the
link disappears, the rest of the document stays valid. Only a page `< 1` is
refused immediately (`@error = 1`).

### Opening mode

| Setting | Values |
|---|---|
| `_PDFX_SetPageMode` | `UseNone`, `UseOutlines`, `UseThumbs`, `FullScreen` |
| `_PDFX_SetPageLayout` | `SinglePage`, `OneColumn`, `TwoColumnLeft`, `TwoColumnRight`, `TwoPageLeft`, `TwoPageRight` |

Case and spaces are ignored (`"useoutlines"` works). An unknown value returns
`False` with `@error = 1`; an empty string restores the automatic choice. After
`_PDFX_Save`, the four navigation functions return `@error = 2`: the document is
frozen.

### Verifying

`Tools/outline.py` reads the tree with no dependency and resolves every
destination to a page number:

```bash
python Tools/outline.py Examples/04_Manual.pdf
# Cover                               page 1  /Fit
# Contents                            page 2  y=739.843
# Reference                           page 5  y=717.165
#   Bookmarks                         page 5  y=552.756
#     Destinations                    page 5  y=382.677
# ---- 11 bookmark(s)
```

`Tools/pdfcheck.py` additionally checks, for every PDF: the `/Outlines` root,
the `First`/`Last` chains, every `/Count`, the `/Annots` of each page and the
internal `[N 0 R ...]` destinations — including the absence of `[0 0 R`.

## 10. Saving and validity

`_PDFX_Save` writes: the `%PDF-1.7` header, a binary comment, the objects, the
`xref` table (exactly 20-byte entries), the `trailer`, and `startxref`. Stream
`/Length` values are those of the bytes actually written.

A document is written **only once**: after a successful save, `_PDFX_Save` and
`_PDFX_AddPage` return `@error = 2` instead of producing a second inconsistent
file. If the file creation fails, nothing is frozen and the call can be retried.

Metadata and identity:

- `/Title`, `/Author`, `/Subject` and `/Keywords` are written as literal strings
  when the text is ASCII, as **UTF-16BE** hexadecimal (`<FEFF...>`) otherwise: a
  title with `€`, `œ` or a CJK character stays exact.
- `/CreationDate` and `/ModDate` are in **universal time**, ending with `Z`
  (`D:20261026184718Z`): the PDF does not depend on the machine's time zone.
- `/ID` is a **deterministic MD5** fingerprint of the content and metadata. Two
  runs over the same document produce the same identifier, which makes
  non-regression measurable.

`Tools/pdfcheck.py` checks all of this with no dependency:

```bash
python Tools/pdfcheck.py Examples/03_Images.pdf
# 03_Images.pdf: 53220 bytes, 10 objects, 3 streams (1 compressed), 0 bookmarks, 0 internal links, OK
```

It checks: header, `startxref` → `xref`, every offset → `N 0 obj`, `/Length`
against the real length, `/Root` and `/Size`, `/Count` against `/Kids`, then the
navigation — `/Outlines` root, `First`/`Last` chains, `/Count` of every
bookmark, `/Annots` and internal destinations of each page. `FlateDecode`
streams are additionally **inflated with zlib**: a corrupt stream or a wrong
length is reported, which validates the compressor end to end.

`Tools/regress.py` guarantees that a change to the engine does not alter a
single byte of the output. The PDFs in `Tests/Reference/` are compared with the
regenerated ones, with timestamps and the `{date}` token neutralized:

```bash
python Tools/regress.py Tests/Reference Examples Tests
# IDENTICAL  01_Report.pdf  (739578b95e1ae4c7)
# IDENTICAL  01_Torture.pdf  (4f460a1dccfb57a6)
# ...
```

## 11. Compression

Content streams make up most of a text PDF. `_PDFX_SetCompression` writes them
as **FlateDecode** (zlib / DEFLATE), with no DLL and no COM, using a compressor
written in AutoIt:

```autoit
_PDFX_SetCompression($pdf, 6)      ; 0 = raw (default), 1..9 = increasing effort
```

| Level | Use |
|---|---|
| 0 | no filter: streams readable by eye in a text editor |
| 1–3 | drafts, interactive generation |
| 6 | recommended default: good size / time balance |
| 9 | archives: searches for the most distant repetitions |

What is compressed:

- the **content streams** of each page, one per page;
- **JPEG** files are left as is: already compressed, stored as `DCTDecode`;
- dictionaries, fonts and metadata are too small to gain anything.

A stream that gains nothing — an almost empty page, already dense content — is
written in clear. The choice is made stream by stream, at save time: the
presence of `/Filter /FlateDecode` is therefore not guaranteed for every page.

Measured results on the examples (AutoIt 3.3.16.1 x86, Windows 10):

| Document | Raw | Level 6 | Gain |
|---|---|---|---|
| `01_Report.pdf` | 18,505 B | 5,775 B | 3.2× |
| `02_Invoice.pdf` | 10,891 B | 3,348 B | 3.3× |
| `03_Images.pdf` | 57,906 B | 53,220 B | 1.1× (JPEG dominant) |

The compressor uses **fixed Huffman** coding and a match search bounded by the
level. It reaches the ratio of zlib level 1, at about 30 KB/s: that is the price
of pure AutoIt with no dependency. The rendering is strictly identical and the
output is **deterministic**: two runs over the same document give the same
bytes, which `Tools/regress.py` verifies.

Compression applies at save time, not at call time. A level out of range is
clamped into `[0, 9]` with `@error = 1`; after `_PDFX_Save`, the document is
frozen and `_PDFX_SetCompression` returns `@error = 2`.

## 12. Accepted limits

- **Optional compression, in pure AutoIt.** It is disabled by default and peaks
  at the ratio of zlib level 1, at about 30 KB/s: a very large document may take
  several seconds. For massive archives, a native tool remains faster.
- **No TTF/OTF embedding.** The 14 standard fonts are used, which guarantees
  identical rendering everywhere with no licence to manage.
- **No PDF reading**: PDFX writes; it does not merge, extract or fill forms.
- **No encryption, no signature, no PDF/A.**
- **Transparency**: global opacity through `ExtGState` (`_PDFX_SetAlpha`), but
  no transparency groups and no soft masks.
- **Gradients**: not provided; approximate them with bands or an image.
- **Navigation limited to the document**: bookmarks and `_PDFX_LinkPage` target
  pages of this PDF only. No named destinations, no JavaScript actions, no
  attachments, no links to another file (`/GoToR`). Bookmarks have no colour,
  weight or icon: title, level and destination only.
- **Progressive JPEG**: accepted as input but rendered inconsistently depending
  on the reader; re-save as baseline JPEG (GDI+ does) to be safe.

## 13. Under the hood

```
document ──► indirect objects (1 Catalog, 2 Pages, then pages, contents,
             fonts, XObjects, ExtGState)
          └► at save time: offsets → xref table → trailer → startxref
```

- Pages are flushed (`_PDFX_FlushPage`) as soon as another one is added.
- Internal links are prepared **before** the pages — the annotation must be in
  `/Annots` from the start — then completed at the end, when the object number
  of every page is known. A dropped link carries object `0` and the second pass
  ignores it.
- The `/Outlines` tree is built after the page loop, in call order: parent,
  previous/next siblings and `/Count` follow directly.
- Each page has its own content stream and its `/Resources` dictionary built
  from the fonts, images and states actually used.
- Colours are normalized to `r g b RG/rg`, coordinates are converted in a single
  pass (`_PDFX_Y`).
- Text is escaped in octal (`\233`) for every non-printable byte, which makes
  accents readable by all readers.

## 14. Troubleshooting

| Symptom | Likely cause |
|---|---|
| The script exits with nothing printed | syntax error: run `Au3Check.exe PDFX.au3` |
| Blank page | no `_PDFX_Text`/shape before the next `_PDFX_AddPage` |
| Accents replaced by `?` | character outside WinAnsi; check the encoding of the `.au3` file (UTF-8) |
| Image missing | path relative to the script: use `@ScriptDir & "\..."` |
| `_PDFX_Image` returns False | file missing, or image not readable by GDI+ |
| `_PDFX_Save` or `_PDFX_AddPage` returns `@error = 2` | the document was already saved: create a new one to continue |
| PDF not smaller despite compression | content already dense (JPEG images) or page almost empty: the engine falls back to the raw stream |
| Compression slow on a large document | the compressor is pure AutoIt (~30 KB/s): lower the level or reserve compression for archives |
| Bookmark missing from the pane | empty title, page outside the document, or bookmarks added after `_PDFX_Save` (`@error = 2`) |
| Link visible but inactive | the target page was never created: the link is ignored at save time |
| The bookmarks pane stays closed | `_PDFX_SetPageMode($pdf, "UseNone")` was requested explicitly, or the reader ignores the opening mode |

## 17. Working in SciTE

Nothing to configure: PDFX is an ordinary include, as comfortable in SciTE-Lite
(shipped with AutoIt) as in SciTE4AutoIt3.

1. `File > Open` → `PDFX\Examples\01_Report.au3`
2. `F5` (Go): Au3Check runs, the PDF is written next to the script.
3. `ConsoleWrite` output appears in the **Output** pane:
   `OK C:\...\01_Report.pdf (5775 bytes, 2 pages)`

Things to know:

- The working directory is the script's directory: `@ScriptDir` points to
  `Examples\`, so relative image paths work without any setting.
- `#Region ... #EndRegion` blocks fold in the margin: handy in a file of more
  than 3,200 lines.
- Encoding: AutoIt 3.3.16 reads UTF-8 without BOM — verified, `"éàç"` gives
  `Len=3` and `AscW=233`. Keep the source in UTF-8 (the SciTE default), not in
  ANSI/CP1252.
- In your own project, include by relative path (`#include "..\PDFX.au3"`) or
  copy `PDFX.au3` next to the script.
- If a script seems stuck **with nothing printed**, it is almost always a
  hidden AutoIt error box behind the window: close it, then add
  `Opt("TrayIconDebug", 1)` at the top of the script to read the current line in
  the tray icon tooltip.
- `Ctrl+Break` (Stop Executing) does not close a modal box: close the dialog,
  otherwise end `AutoIt3.exe` in Task Manager.
